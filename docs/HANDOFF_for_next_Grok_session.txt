4. PRODUCTION SERVER CHANGE (DIRECT — NOT VIA GITHUB DEPLOY)
================================================================================

WHY:
  Desktop app needed "Login and Load My Proxy".
  Production architecture:
    - Public: nginx → gunicorn website.py on 127.0.0.1:5000 (HTTPS 443)
    - Internal only: radius-api app.py on port 5001 (check_credentials, get_proxy, etc.)
    - Port 5001 is firewalled (not reachable from internet)
  So the desktop cannot call 5001 directly. Needed a public HTTPS JSON endpoint
  on the website that proxies to 5001 on localhost.

WHAT WAS DONE (SSH as root to 87.106.110.122):
  1. Backed up website.py:
       /opt/proxypi/backups/website.py.bak_desktop_api_<timestamp>
  2. Inserted route into /opt/proxypi/website.py:
       POST /api/desktop/login
  3. py_compile syntax check
  4. systemctl restart proxypi.service

ENDPOINT CONTRACT:
  POST https://proxypi.co.uk/api/desktop/login
  Content-Type: application/json
  Body: { "email": "...", "password": "..." }   // website account credentials

  Success 200:
  {
    "ok": true,
    "email": "...",
    "proxy": {
      "host": "<dns_record>",
      "socks_port": <int>,
      "http_port": <int>,
      "username": "<RADIUS username>",
      "password": "<RADIUS password>"
    },
    "usage": {
      "total_mb": ...,
      "threshold_mb": ...,
      "status": "...",
      "trial_status": "...",
      "rotation_mode": "..."
    }
  }

  Failures:
    400 missing fields
    401 invalid email/password
    404 no active plan / no proxy assigned
    502 incomplete data / internal API error

  Internally the website calls RADIUS_API_URL (default http://127.0.0.1:5001):
    GET /check_credentials?username=&password=
    GET /get_usage?user_email=
    GET /get_password?username=   (if password not already in usage)
    GET /get_proxy?user_email=

  Note: internal API still uses GET + password in query string for check_credentials
  (pre-existing website pattern). Desktop login itself uses POST JSON over HTTPS.

SERVICES:
  proxypi.service     → gunicorn website:app on :5000
  radius-api.service  → python app.py on :5001
  nginx               → 443 → 5000

RECONCILE WITH GITHUB (USER SHOULD DO):
  Copy the /api/desktop/login block from production website.py into the
  GitHub-managed website repo, commit, and deploy so the next GitHub deploy
  does not wipe the live endpoint.

5. DESKTOP APP BEHAVIOUR (v1.1.x)
================================================================================

Login flow:
  User enters ProxyPi website email + password
  App POSTs to https://proxypi.co.uk/api/desktop/login
  On success: fills Host, SOCKS/HTTP ports (both stored), RADIUS user/pass, auth on
  Type dropdown: SOCKS5 vs HTTP swaps g_socksPort / g_httpPort without re-login

Tests:
  Test Proxy → api.ipify.org via proxy → exit IP + latency
  Speed Test → IP check + ~1MB download via speedtest.tele2.net → Mbps
  Tip: first latency can be higher due to DNS + cold path

UI:
  Dark ProxyPi branding, About (version + support@proxypi.co.uk)
  Tab navigation between fields (IsDialogMessage)
  No "&" in "Login and Load My Proxy" (Win32 accelerator underline issue)

Updates:
  Quiet check on startup + Help → Check for Updates
  Reads public update.json / GitHub Releases (no tokens in the client)

Version constant: APP_VERSION in src_simple/main.cpp (was 1.1.0 at last ship)
  Support line added to About; rebuild Release if not yet in published zip.

================================================================================

- EXE is reverse-engineerable; treat client as public; secrets stay on server.
- Download zip must never include ProxyPiTester.ini or proxydetails.
- Production /api/desktop/login rate limiting (6) is LIVE:
    10 fail / 15m / IP, 5 fail / 15m / email, 30 total / 15m / IP → HTTP 429
    File store: /opt/proxypi/data/desktop_login_rl.json (fcntl lock, multi-worker)
